BERT 的双向不是噱头——把 GPT 因果 mask 换成全连通 mask，每个 token 都能看到整个上下文，模型被迫学会真正的语义融合。

引子：同样用 Transformer，“双"在哪？

上一篇拆了 Transformer，它的核心是 self-attention——理论上能看上下文所有 token。但 2018 年 OpenAI 的 GPT-1（Radford et al.）把 Transformer Decoder 拆出来做自回归语言模型，每一步只允许看自己和过去的 token。

这就像读句子时只准往前看，不能回头。句子"小明给小红 ___ 一本书"里的填空位置——，读到这里，GPT 只能根据"小明给小红"猜下一个词，看不到后面"一本书"这个宾语给出的提示。语义判断需要"两头看”，单向约束就成了天花板。

BERT（Bidirectional Encoder Representations from Transformers）的"Bidirectional"就是为这件事准备的。

但"BERT 比 GPT 多看了一头"这件事，真正的实现代价极小——架构几乎一样，只是 attention mask 不同。难的不是"让 token 互相看"，难的是"看完之后模型还能不能学到东西"。本文就讲这三件事：

  1. 怎么"双"：attention mask 的差异
  2. 双了之后怎么训练：为什么必须用 MLM 而不是 LM
  3. 到底有多大用：消融数据说了什么

一、“双"在 attention mask

GPT 和 BERT 都用 Transformer encoder block，唯一的架构差异就在 attention mask。这个差异用一张图就能讲清楚。

设输入长度为 7（含 [CLS]/[SEP]），mask 矩阵里 1 表示"看得见”，0 表示"看不见"：

我 喜欢 猫 睡 在 沙发 上
1 0 0 0 0 0 0     ← 预测"我"时只能看自己
1 1 0 0 0 0 0     ← 预测"喜欢"时看"我""喜欢"
1 1 1 0 0 0 0     ← 预测"猫"时看"我""喜欢""猫"
1 1 1 1 0 0 0     ← 预测"睡"时看前 4 个
1 1 1 1 1 0 0     ← 预测"在"时看前 5 个
1 1 1 1 1 1 0     ← 预测"沙发"时看前 6 个
1 1 1 1 1 1 1     ← 预测"上"时看全部

这是一个下三角矩阵。每个 token 的感受野从自己扩展到整个前缀，但永远看不到右边。12 层叠加后，每层感受野都受这个 mask 约束——信息只能从左向右流动。

BERT（Bidirectional Mask）

1
2
3

我 喜欢 [MASK] 睡 在 沙发 上
1 1 1 1 1 1 1     ← 预测 [MASK] 时看全部 7 个位置
1 1 1 1 1 1 1     ← 其他位置的注意力也一样

这是一个全 1 矩阵。每个位置都能 attend 到所有位置——包括自己、包括后面、包括其他 [MASK]。12 层之后，每个 token 的最终表示都已经融合了整个序列的左右上下文。

这就是"双"的全部含义。**没有新增任何参数，没有改变 layer norm / FFN / 残差结构，没有改变 token 化方式。**只是一张 mask 矩阵从下三角换成全 1，模型就从"语言模型"变成"双向编码器"。

但这件事带来一个直接问题——下一节就要解决。

二、双向之后，为什么不能继续用 LM？

把 mask 改成全 1，self-attention 在数学上是合法的。但自回归语言模型的目标函数不再成立：

给定前缀 $w_1, w_2, \ldots, w_{t-1}$，预测下一个 token $w_t$。

如果模型在预测 $w_t$ 时能"看到" $w_t$ 本身（比如直接 attend 到 $w_t$ 位置），那损失函数就变成了"用答案预测答案"——模型的最优解是直接拷贝输入，学不到任何语义。

直觉演示：句子"猫坐在垫子上"，用 LM 目标 + 全 1 mask 训练时：

1
2

目标：给定"猫坐在垫子上"预测第 3 个 token
模型：看见全部输入 → 直接输出"坐"

这等价于把 LM 目标降级成"抄写"。所以 BERT 必须改训练目标——这就是 MLM（Masked Language Modeling）的来源。

三、MLM：用 cloze 任务绕开标签泄漏

BERT 论文借鉴了 Taylor 1953 年的 Cloze 任务：把句子挖个空，让模型填回去。具体做法分两步。

3.1 选位置：随机遮 15%

原文措辞：

“In all of our experiments, we mask 15% of all WordPiece tokens in each sequence at random.”

15% 这个数字是直接选定的启发值，原论文没有给出 sweep 消融——附录 C.2 的 Table 8 是 mask 策略（80/10/10）的消融，不是 mask rate 的消融。

直觉上：

  • 太低（如 5%）→ 训练信号太弱，模型收敛慢；
  • 太高（如 50%）→ 输入被破坏得太厉害，连续语言结构难以学到。

15% 是个折中——每个序列平均有 76 个 token（512×0.15），既够密又不至于把句子打散。

3.2 替换策略：80/10/10

被选中的 15% token 不能简单替换成 [MASK]——否则预训练时见过 [MASK]，微调时没有 [MASK]，分布严重不匹配。

原文解决方案：

“If the i-th token is chosen, we replace the i-th token with (1) the [MASK] token 80% of the time (2) a random token 10% of the time (3) the unchanged i-th token 10% of the time.”

举例（来自原文附录 A.1，“my dog is hairy”）：

1
2
3
4
5

原始:    my dog is hairy
↓ 选中第 4 个 token "hairy"
80%:     my dog is [MASK]        ← 标准 MLM
10%:     my dog is apple         ← 随机替换
10%:     my dog is hairy         ← 保持原样

最后那 10% 保持原样看似没意义，其实很关键：模型永远不知道当前 token 会不会被要求预测，所以必须为每个 token 都维护一个完整的语境表示（contextualized representation），而不是只对 [MASK] 位置"特殊对待"。

10% 的随机替换则让模型被迫学一个隐式的"合理性判别"——不能因为 90% 的位置是 [MASK] 就把 [MASK] 当成背景噪声忽略掉。

3.3 损失只在被遮位置计算

伪代码（BERT 原文逻辑）：

1
2
3
4

logits = bert(masked_input)              # [batch, seq_len, vocab]
loss = cross_entropy(logits, target_ids) # 算所有位置
loss = loss * mask_weights               # 只在被遮位置保留梯度
# mask_weights: 被遮位置 = 1, 其余 = 0

模型 100% 的前向计算照常发生（被遮位置也要参与 attention），但只有 15% 的 token 产生梯度。原论文附录 A.2 的原话：

“Compared to standard language model training, the masked LM only makes predictions on 15% of tokens in each batch, which suggests that more pre-training steps may be required for the model to converge.”

这也是 BERT 训练 1M 步（≈40 epoch）的部分原因——单步有效信号只有自回归 LM 的 15%，需要更多步补偿。

附录 C.1 还有一个图（Figure 5），曲线说明 MLM 收敛速度确实比 LTR 慢一点，但很快就在绝对准确率上反超 LTR。

四、NSP：第二个预训练任务的真相

4.1 任务定义

输入两段文本 [CLS] A [SEP] B [SEP]：

  • 50% 概率：B 是 A 的真实下一句（label = IsNext）
  • 50% 概率：B 是从语料里随机抽的（label = NotNext）

用 [CLS] 位置的输出做二分类。原文（Section 3.1.2）：

“we demonstrate in Section 5.1 that pre-training towards this task is very beneficial to both QA and NLI.”

4.2 消融数据说了什么

论文 Table 5（BERT_BASE 架构，Dev Set）：

任务 MNLI-m QNLI MRPC SST-2 SQuAD F1
BERT_BASE（完整） 84.4 88.4 86.7 92.7 88.5
No NSP 83.9 84.9 86.5 92.6 87.9
LTR & No NSP 82.1 84.3 77.5 92.1 77.8

去掉 NSP 后：

  • QNLI 掉了 3.5 点（88.4→84.9）—— 这是最大跌幅，QNLI 是句间关系任务，NSP 直接相关。
  • MNLI 掉了 0.5 点（84.4→83.9）—— 几乎没影响。
  • SST-2 掉了 0.1 点—— 几乎无影响（SST-2 是单句情感分类）。
  • SQuAD 掉了 0.6 点—— 小幅下降。

**所以"去掉 NSP 掉 1-2 个点"是一个粗略说法，真实情况是任务相关、且主要体现在 QNLI 上。**论文原文（Section 5.1）的措辞也比较克制：“removing NSP hurts performance significantly on QNLI, MNLI, and SQuAD 1.1"——而 Table 5 里 MNLI 其实只掉 0.5 点，“significantly” 更准确地说应该是 QNLI。

4.3 NSP 后来被质疑（RoBERTa 的实证）

RoBERTa（Liu et al. 2019）专门做了 NSP 的对照实验，论文 Section 4.2 的 Table 4 直接列出了数字：

输入格式 SQuAD 1.1/2.0 MNLI NLI Avg RACE
SEGMENT-PAIR + NSP（BERT 原版） 90.4 / 78.7 84.0 92.9 64.2
SENTENCE-PAIR + NSP 88.7 / 76.2 82.9 92.1 63.0
FULL-SENTENCES, 无 NSP 90.4 / 79.1 84.7 92.5 64.8
DOC-SENTENCES, 无 NSP 90.6 / 79.7 84.7 92.7 65.6

去掉 NSP 后：

  • SQuAD F1：90.4→90.4（持平）
  • MNLI：84.0→84.7（+0.7）
  • RACE：64.2→64.8（+0.6）

也就是说，RoBERTa 的复现直接推翻了 BERT 论文"去掉 NSP 会掉点"的判断——在更大数据（160GB vs 16GB）、更长训练下，去掉 NSP 不仅不损失，反而整体略好。RoBERTa 摘要里把”removing the next sentence prediction objective“列为四大改进之一。

后续 ALBERT（Lan et al. 2020）则提出 SOP（Sentence Order Prediction）——把"判断是否相邻"换成"判断句序是否正确”，更难、更能学到句间连贯性，进一步说明 NSP 任务本身设计粗糙。

所以 NSP 的真正价值不是"句子级表示有多必要"，而是证明了"预训练任务可以不止一个"——MLM 学 token 级，NSP 学句间关系，两者互补。这个多任务预训练的思路被后续 ELECTRA、SpanBERT、ALBERT 等沿用，只是具体任务换了。

五、几个常被搞错的细节

原文核完，几个流传很广但实际上是错或夸张的说法，在这里一并澄清。

5.1 “BERT 是第一个用 GELU 的模型”

错。GELU 由 Hendrycks & Gimpel 在 2016 年提出（arXiv:1606.08415），但第一个把它用在 Transformer LM 预训练的是 GPT-1（2018 年 6 月）。

GPT-1 原文（Section 3.2）的原话：

“For the activation function, we used the Gaussian Error Linear Unit (GELU) [18].”

BERT 附录 A.2 的原话：

“We use a gelu activation (Hendrycks and Gimpel, 2016) rather than the standard relu, following OpenAI GPT.”

BERT 论文自己都写"following OpenAI GPT"——BERT 不是 GELU 的发明者，是接力者。

5.2 “BERT 的掩码率是消融得到的”

错。15% 没有 sweep 实验支持，是直接选定的启发值。原文 Table 8 的消融只对比 80/10/10 这种 mask 策略的分布，不对比 mask rate 本身。

后续工作（“Should You Mask 15% in Masked Language Modeling?"，arXiv:2202.08005）专门重新研究过这个数字，发现在 RoBERTa 训练规模下，20% 反而略好于 15%，但作者也认为差异不显著。所以 15% 不是"最优解”，是"够用"。

5.3 “SQuAD 微调时没有额外参数”

错。SQuAD 的 start / end 预测是基于 BERT 输出加一层线性层：

1
2

start_logits = W_s · h_i + b_s   # W_s: H × 1
end_logits   = W_e · h_i + b_e

这里的 $W_s, W_e$ 就是新增参数（BERT-base 是 768 维，所以每个向量 768 个权重）。原文章把它们省略掉会让读者误以为没有参数。

5.4 “BERT 让所有 NLP 任务不再需要任务特定架构”

夸张。原文强调"minimal task-specific parameters"——只是参数变少了，不是没了。SQuAD 需要 start/end 头，序列标注需要 token-level 分类头，多任务需要任务路由。BERT 的贡献是降低下游任务对架构工程的依赖，不是消灭它。

六、架构与训练速览

BERT 的输入由三种 embedding 逐元素相加得到：

  • Token Embedding：WordPiece 分词，词表 30,000
  • Segment Embedding：标记 token 属于句子 A 还是 B（NSP 需要）
  • Position Embedding：可学习的位置向量，最大 512

为了后文参考，把核心数字整理成一张表。所有数字都来自 BERT 原论文 Section 3 / Appendix A。

参数 BERT-base BERT-large
层数 L 12 24
隐藏维度 H 768 1024
注意力头 A 12 16
FFN 中间维度 3072 4096
总参数 110M 340M
词表（WordPiece） 30,000 30,000
最大位置 512（可学习） 512

预训练（Appendix A.2）：

  • 优化器：Adam，lr=1e-4，β₁=0.9，β₂=0.999，L2 weight decay=0.01
  • 学习率调度：前 10,000 步 warmup 线性增长到 1e-4，之后线性衰减
  • Batch size：256 序列 × 512 tokens = 128,000 tokens/batch
  • 训练步数：1,000,000 步（≈40 epochs over 3.3B word corpus）
  • 序列长度调度：90% 步用 128 tokens，10% 步用 512 tokens——这是为了在注意力是 O(n²) 的代价下，加速训练同时让位置编码学到 512 的范围
  • Dropout：0.1（所有层）
  • 激活函数：GELU（from GPT-1）
  • 数据：BookCorpus (800M words) + English Wikipedia (2,500M words)
  • 硬件：BERT-base 用 4 块 Cloud TPU（Pod 配置，共 16 chip）；BERT-large 用 16 块 Cloud TPU（64 chip），训练约 4 天

微调（Appendix A.3 的推荐范围）：

  • Batch size：16 或 32
  • 学习率：2e-5、3e-5 或 5e-5
  • Epochs：2、3 或 4

七、MLM vs 自回归：几个常见误读

读 BERT 资料时常见的几个说法，正好借这里澄清。

7.1 “MLM 比 LM 高效，因为只算了 15%”

半对半错。前向计算是 100% 进行的——所有 token 都要参与 attention。变少的只是反向梯度的来源。换句话说：

  • 自回归 LM：每步 100% 前向 + 100% 位置有梯度 = $O(n^2)$ attention × 全序列梯度
  • BERT MLM：每步 100% 前向 + 15% 位置有梯度 = $O(n^2)$ attention × 15% 梯度

梯度来源减少意味着每次更新更"轻"，但代价是有效信息密度低、需要更多步——这正是 BERT 训练 40 epoch 的部分原因。

7.2 “BERT 预训练是完形填空，所以学到了理解能力”

不严谨。“完形填空"只是训练信号的形状，模型学到的不是"填空技巧”，而是 contextualized representation——每个 token 的表示已经融合了左右上下文。这种表示迁移到分类、问答、NER 时，不需要从零学语义，所以微调代价小。

7.3 “BERT 因为双向所以更强”

部分对。消融（Table 5）告诉我们：

  • BERT_BASE（双向 + NSP）：MNLI-m = 84.4
  • LTR & No NSP（单向 + 无 NSP）：MNLI-m = 82.1
  • 差距 2.3 个点

这个差距主要来自 SQuAD 和 MRPC 这类需要 token 级双向上下文的任务——SQuAD 掉 10.7 点，MRPC 掉 9.2 点。但 SST-2（单句情感）只掉 0.6 点，说明"双向"的优势是任务相关的。

八、BERT 的真实贡献

到这里可以回答标题的问题了。“双"在 attention mask，“双"的价值在哪？三层：

8.1 架构层：让 token 看到全部上下文

代价是 mask 矩阵从下三角换成全 1，架构主体不变。这一改让 Transformer Encoder 的"双向上下文融合"能力第一次在大规模预训练中被完整释放。

8.2 训练层：MLM 解决了"看见自己"问题

如果只在架构上"双”，模型会退化成抄写机器。MLM 通过遮蔽 + 80/10/10 替换，把"双向"从架构属性变成了预训练目标的一部分，让损失函数本身不泄漏标签。

8.3 范式层：通用预训练 + 轻量微调

BERT 把 NLP 的范式从"每个任务设计专属架构"转向"通用 backbone + 任务特定头部”。这种范式在 BERT 之前 ELMo 已有（特征拼接），但 BERT 用 fine-tuning 把这种范式推到了 SOTA——为后续 RoBERTa、ALBERT、SpanBERT、ELECTRA 提供了同一条路线。

九、BERT 的局限

讲完优点也要讲局限：

  1. 最大长度 512——可学习位置编码的限制，长文本任务（文档级 QA、长文档分类）需要截断或用 Longformer 这类变体。
  2. 预训练-微调 mismatch——虽然 80/10/10 缓解了，但 [MASK] 在微调时永远不出现，仍然是个 bias。
  3. 不适合生成——Encoder-only 架构看不到"未来"，解码要靠 autoregressive head。T5、BART 这类 Encoder-Decoder 才是生成的主流选择。
  4. NSP 训练效率低——50% 的训练样本是随机句对，对表征学习的贡献被后续工作质疑。
